# Governance

BrandTrace is developed by Ember Fire Media. This document describes how decisions are currently made and how the project intends to involve other developers.

## Current Status

BrandTrace is in an early public soft-launch phase. Final authority on mission alignment, verification standards, and publication of verified records currently rests with Ember Fire Media.

This is intentional while the project is still establishing its data quality bar and contribution processes.

## Decision Areas

| Area | Current Decision Maker | Notes |
|------|------------------------|-------|
| Mission, philosophy, and core principles | Ember Fire Media | Changes require clear public rationale |
| Verification Protocol and what counts as “Verified” | Ember Fire Media + documented standards | Community can propose improvements |
| Code, architecture, and technical direction | Ember Fire Media with open contribution | Pull requests welcome; maintainers review |
| Public verified database content | Review process (initially Ember Fire Media) | Community submissions must pass review |
| Funding and advertising acceptance | Ember Fire Media under FUNDING_AND_ADVERTISING.md | Must stay mission-aligned |
| Day-to-day issue triage and roadmap prioritization | Maintainers | Community input encouraged |

## Path to Broader Participation

As the project matures, the intention is to:

1. Invite trusted contributors to help with code review and technical decisions.
2. Establish a small review group for verification decisions once volume requires it.
3. Keep the Verification Protocol, Mission, and Funding policy as public, versioned documents that anyone can read and propose changes to.
4. Never allow the verified ownership database to become a vehicle for political campaigns, unsupported accusations, or paid influence.

## Contributor Rights and Expectations

- Anyone may open issues, submit pull requests, or propose documentation and data-model improvements.
- Factual ownership claims require sources and remain in “pending / community submission” status until reviewed.
- Maintainers may request changes, close out-of-scope proposals, or reject contributions that conflict with the Mission, Verification Protocol, or Code of Conduct.
- Disagreements about verification should be resolved by improving source quality and documentation, not by majority vote on contested facts.

## Transparency

- Major policy changes will be committed to this repository.
- Verification decisions for public records should leave an auditable trail (reviewer notes, sources, status changes).
- The project will not silently rewrite history of verified claims; corrections are documented.

## Future Evolution

This governance model is expected to evolve. When a more formal structure (for example a small stewardship group or documented maintainer team) becomes useful, it will be proposed publicly and recorded here.

Until then, the guiding question for every decision remains the same:

> Does this increase transparency, improve trust, empower consumers with verifiable information, and remain neutral?
